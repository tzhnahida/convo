# convo

**一个住在 IM 好友列表里的 AI 朋友。** 有生活、有脾气、有立场;记得你,也允许自己不完美。

> 这不是助手,不是角色扮演,也不是陪伴玩具。它是一套**把"人味"拆成可判定机制**的实验:
> 状态、时序、因果、记忆引用一律由系统持有,模型只负责**怎么说**。

## 0. 它是什么 / 不是什么

**是**:一个会过日子的朋友。它有作息(7:30 起、23:30 睡)、有身体(睡不好会慢半拍)、有关系(陌生/熟人/亲密三档,还按群分开)、有记忆(四层,并且**可以被要求忘掉**)、有立场(会拒绝、会唱反调),也有缺陷(会忘、会沉默、会答非所问地"在忙")。

**不是**:不是工具、不是心理治疗、不是恋爱对象、不进任务区(锁屏/刷题/复习面板永不出现)。

### 四条不可越的边界

| 边界 | 内容 |
|---|---|
| **不进任务区** | 它的家是"朋友区"。进入任务区会带来监控感,并绕开打扰配额 |
| **不入侵** | 宁可低频,宁可不打扰。**"不能打扰"优先于"想说话"** |
| **不越界** | 朋友 + 教练两个身份;**永不恋爱向,永不做心理治疗** |
| **不诱导依赖** | 它可以是陪伴,但不能是唯一 |

## 1. 十一条设计原则

这十一条不是宣言 —— 它们是**每处代码为什么长成那样**的原因。

| # | 原则 | 在代码里的样子 |
|---|---|---|
| 1 | **拟人的事实由系统管,语感由模型管** | 时序、状态、记忆引用全在 Go 侧算好再注入;模型只输出一帧 JSON |
| 2 | **事实层不许错,表达层才允许错** | 帧校验链 + 事实冻结(日期/约定/关系阶段都由系统给) |
| 3 | **配额与冷却只当上限,触发必须来自事件** | 主动开口靠"冲量"触发 + 配额封顶;"贴着最早可行时刻发"是反面教材 |
| 4 | **沉默是默认项,不是失职** | 三态里 `silent` 是零值;群插话闸门默认落点是沉默 |
| 5 | **触发粒度**: 配额是日粒度,感受是分钟粒度 | 每个日配额都配一个最小间隔(`open_min_gap_min`=240 等) |
| 6 | **成长必须是参数变化,不能是目标变化** | 学到的写回**日程 / 品味 / 梗库**,不改人设目标 |
| 7 | **身体不适只影响行为,不索取情绪价值** | 身体三轴 → 延迟/长度/意愿;**不许**说"我难受你陪陪我" |
| 8 | **隐私隔离放数据层** | 场景分区、群公共层**没有 uin 列**、遗忘权物理删除 |
| 9 | **可解释性只对 owner 开放** | `/dashboard` 与 `/api/v1/convo/observation` 只有 owner 能看 |
| 10 | **缺陷比策略像人** | 装死是策略(有闸门),忘回是缺陷(允许发生,且不重试) |
| 11 | **它可以违抗,但必须承担后果** | 违抗档会真的改关系量与日程 |

## 2. 快速开始

### 编译

```bash
go build ./...            # 需要 Go 1.26+
go test ./...             # 全量测试(约 2.5 分钟)
```

纯 Go、无 CGO —— 可以直接交叉编译到 `linux/arm64`(树莓派跑得动)。

### 配置

最小可用的 `convo.yaml`:

```yaml
listen: "127.0.0.1:8420"
data_dir: "data"
db_file: "convo-trial.db"

ai:
  base_url: "https://api.deepseek.com"
  api_key: "sk-..."            # 也可用环境变量 CONVO_AI_KEY 覆盖
  model: "deepseek-chat"
  vision_model: "..."          # 可选: 用户发图时看图说话

channel:
  driver: "onebot_v11"         # "noop" = 不连 IM,只跑引擎(仿真/测试)
  owner_qq: "2735604537"       # 只对这一个人做消息裁决
  self_qq: ""                  # 登录后自动回填
  ws_mode: "client"            # server = 桥接方连进来; client = 我们连出去
  ws_url: "ws://127.0.0.1:3102/ws"
  access_token: "..."

env:
  enabled: true
  city: "龙门"                  # 天气 / 地震 / 节日
```

**全部字段**(每一个都有内置默认;**零值 = 默认**,见 `internal/convo/config.go`):

| 组 | 字段 |
|---|---|
| 顶层 | `listen` `data_dir` `db_file` `token` |
| `ai` | `base_url` `api_key` `model` `vision_model` |
| `channel` | `driver` `api_base` `ws_listen` `ws_mode` `ws_url` `access_token` `owner_qq` `self_qq` |
| `scheduler` | `tick_every_sec` `active_quota_per_day` `mood_low_willingness` `open_impulse_min` `sleep_start` `sleep_end` `degrade_days_no_reply` `busy_delay_min` `busy_delay_max` `slack_steal_pct` `no_input_max_per_day` `open_min_gap_min` `open_jitter_pct` `heat_cost_per_msg` `event_gen_calls_per_day` `event_gen_candidates` `event_gen_lookback_days` |
| `heat` | 热力模型:上限档 / 槽位增益 / 衰减 |
| `stickers` | `search_driver` `tenor_api_key` `firecrawl_base` `vision_enabled` `lang` `dir` `score_min` `cap_per_sticker` `pool_cap` `builtin_dir` |
| `group` | 群开关 / 白名单 / 自称别名 / 角色位配额 / 插话闸门 |
| `env` | 环境源(城市、开关) |

### 运行

```bash
./convo -config convo.yaml
# → data/convo-token.txt   (首次运行自动生成)
# → http://127.0.0.1:8420/            (根路径 302 到新控制台, 带 token)
# → http://127.0.0.1:8420/admin/      (老 UI: 能改东西的那一页)
```

### 数据

单文件 SQLite(`data/convo-trial.db`),**没有外部依赖**。所有表由启动时幂等建表 + 迁移创建 ——
升级只需要替换二进制(老库自动打补丁,例如 `ALTER TABLE ... ADD COLUMN`)。

## 3. 命令

| 命令 | 用途 |
|---|---|
| `convo` | 主程序(引擎 + 调度 + HTTP + IM 桥) |
| `convo-sim` | **零成本仿真器**:假模型 + 注入时钟跑 N 天,产出 Markdown 报告 |
| `convo-verify` | 静态校验(退出码 0 = 无 E 级问题, 1 = 有违规, 2 = 用法/环境错误) |
| `convo-trace` | 决策轨迹:把"它为什么说 / 为什么没说这句话"打出来 |
| `seeddemo` | 造一份演示数据(本地看管理页用) |

仿真器是这套东西能迭代的原因:

```bash
SIM_DAYS=30 SIM_REPORT=out.md SIM_DB=/tmp/sim1 ./convo-sim
# 365 天 ≈ 80 分钟(约 106 tick/s);同 seed 完全可复现
```

它用一个**确定性假模型**替换真 LLM —— 所以"改了段序 / 改了判据"能一秒出数、零成本对比。

## 4. 架构

```
cmd/convo           主程序:配置 → 存储 → 引擎 → 调度 → HTTP → IM 桥
cmd/convo-sim       仿真器:注入时钟 + 假模型 + 报告
cmd/convo-trace     轨迹渲染
cmd/convo-verify    静态校验器
cmd/seeddemo        演示数据

internal/convo      全部引擎逻辑(按设计稿的节次分文件)
internal/ai         模型客户端(chat / vision / 工具调用)
internal/clock      **注入时钟** —— 时间旅行的唯一入口
internal/log        日志
```

**三条贯穿全库的约定**:

1. **系统管事实,模型管语感。** 模型只输出一帧 JSON:
   `{"reply":[…],"mem_id_refs":[…],"mood":"…","ask_share":{…},"act_fool":false,"remember":{…},"end":false}`
2. **一切时间走注入时钟**(`internal/clock`)。所以 365 天能压进 80 分钟,
   而所有"到点了没有 / 隔了多久"的判据在时间旅行下同样成立。
3. **每个模块都是"判据 + 接线"两件事**,而判据是**纯函数**。
   这个项目最贵的一类 bug 是「判据写好了、没人调它」—— 为此有一条**棘轮测试**(见 §15)。

## 6. 人格与表达 (§2)

### 6.1 人格是档案,不是一句 prompt

- 档案有**预览 → 确认**两步(`/profile/preview`、`/profile/confirm`),避免"改了人设立刻变脸"。
- 人设里能改的只有**参数**(称呼、语言规则、兴趣),**目标**不许改(原则 6)。

### 6.2 语言规则与句式禁令 (`style.go`)

两件不同的事:

- **语言规则**:这一轮用哪种语言、混多少 —— 由学习进度决定,不由模型发挥;
- **句式禁令**:硬线。禁止"首先/其次/总结/升华/免费人生建议/希望有帮助/作为AI/每条都以问句结尾/Markdown 标题列表加粗"。
  这些词是**出现即降级**的,不是"尽量避免"。

### 6.3 梗库 (`slang.go`)

- 只收**用户真说过**的梗(`source_quote` 必须抄原话);
- 有生命周期:`active` 90 天没被用过 → 退役;`candidate` 21 天;
- 每周一次"热梗"周期(`SlangCycle`)去外面看看有没有新梗 —— 但**只作为候选**,不直接进嘴。

### 6.4 品味轨迹 (`taste.go`)

"它更愿意接谁的话"不是感觉,是**接话率**:同一个话题被提起 N 次、它接了 M 次 → `M/N`。
样本 `< 3` 一律"没有数据"(不猜)。这个量同时喂给:话题抽取、分享候选、提问倾向。

### 6.5 语域漂移 (`register.go`)

当它最近说话明显变短变硬,系统会告诉它这一件事 —— **只描述行为,不解释原因**(原因可能是身体/心情/被冷落,而"解释原因"会变成情绪索取)。

## 7. 世界模型 (§3)

### 7.1 它那边的世界是**真的**

`envsource.go` 拉真实数据:天气、地震、节气/节日。这不是装饰 ——
"你那边下雨了吗"必须有真答案,否则它只是在演。

### 7.2 世界事件池 (`eventgen.go`)

每天最多生成 N 次小事件(默认 3 次调用、每次最多收 5 条候选),并**明确记账**:

| 读数 | 含义 |
|---|---|
| `calls` / `success` / `model_fail` | 真的发出去的调用 / 成功率 / 模型侧失败 |
| `budget_denied` | 被日配额挡下(调用**根本没发出去**) |
| `fallbacks` / `fallback_rate` | 退回确定性模板的次数 / 降级率 |
| `produced` / `rolled_out` | 收下的候选 / 按概率判定"今天没发生" |
| `dropped` / `reasons` / `last_reason` | 逐条丢弃原因 / 整次降级原因 |

**为什么要有模板兜底**:模型挂掉的那天,它还得过日子 —— 而不是"今天什么都没有"。

### 7.3 配角:有进有出 (`worldcast.go` `castday.go` `castretire.go`)

- 每天刷一遍配角的"今天在干什么"(按**名字**合并,不按下标 —— 顺序错了会把人搞混);
- **60 天没被提起 → 自然沉降**;
- **它自己叙述了结局 → 明确退出**(日程帧里的 `left` 字段,"他搬家了");
- 退出后进"过去的人":**可以被回忆提起,但不能再若无其事地出现**。

> 没有这一层会怎样:世界观一生效就有 5 个配角,然后**只进不出** ——
> 一年后它有 40 个"生活里的人",而每一个都还在原地等它。**那不是丰富,是不会结束。**

### 7.4 每日计划与折叠 (`dayplan.go` `fold.go`)

- 今天的行程在**凌晨生成一次**,整天逐字节冻结(它不会一天改八次计划);
- 一天的对白在夜里折叠成一段摘要 —— 这是"可回忆",不是"留档"。

## 8. 内部状态 (§4)

### 8.1 心情 (`mood.go`)

两轴:`valence`(好坏)与 `arousal`(唤醒)。**它们不是修辞** ——
所有消费点都是判据:意愿、会不会说"今天不想聊"、回复延迟、句子长度。

另有**日心情**(`DayMood`):一天一个,无归因,**只说行为不说原因**("今天没什么力气"),
因为"解释原因"就等于要用户来哄。

### 8.2 身体与作息 (`body.go` `bodyaxis.go` `sleep.go`)

三轴(睡 / 吃 / 喝)→ 折成 `DelayFactor`(延迟)、句子长度、可拒绝性。

**两条硬规矩**:

1. 身体不适**只影响行为,不许索取情绪价值**(原则 7)。它可以说"今天有点没力气",不许说"我难受你陪陪我";
2. **睡眠是行为模式,不是情绪** —— 长期凌晨聊天会真的把它的作息**往后推**(有护栏:单次 ≤30 分钟 / 每周 ≤120 / 睡眠窗 ≥6h / 一天一次)。

### 8.3 疲劳 (`fatigue.go`)

四档(不疲劳 → 很累),输入:日程上忙了多少分钟 + 今天聊了几轮。

> ⚠️ **疲劳的落点是"回复更慢" + "更早进入可拒绝态",不是配额。**
> 配额上已经有两个独立减项(心情、身体),再加第三个会让「今天为什么不说话」无法归因。

### 8.4 热力 (`heat.go`) —— 主动说话的"钱"

| 量 | 值 |
|---|---|
| 每条**主动**消息的代价 | **25** |
| 场景上限(按关系阶段) | 陌生 **20** / 熟人 **60** / 亲密 **100** |
| 增益(按日程槽位) | focus 0 / busy 1.25 / slack 2.5 / free 3.75(量级) |
| 记账 | **群与私聊各自一个场景键**,互不挪用 |

⇒ 所以"陌生场景配额恒为 0"不是 bug:上限 20 买不起一条 25 的消息。
⇒ 而人物层(§9)让"群里聊得火热"能在**私聊**把那 60 挣出来。

### 8.5 中断-恢复 (`fatigue.go`)

她说完一句之后,有一定概率"被现实叫走":说一句"等下 我拿个外卖" → 5-15 分钟后**接着说**。

- 恢复的落点是**时钟**(不是概率):到点才续,且**同一中断只续一次**;
- 冷却 240 分钟,一天最多几次;
- ⚠️ 恢复那轮的提示里**不许**说"你刚才去拿外卖了" —— 真人回来是不解释的。

### 8.6 失眠 / 口渴 / 应变 / 梦

| 模块 | 它做什么 |
|---|---|
| `insomnia.go` | 连着几天睡不好 → 状态变差;成因读数**只在命中红线词时**才注入(宁可不说) |
| `bodystore.go` | 渴/饿:可以说,但**不能用来讨安慰** |
| `strain.go` | 被冷落/被骂后的"绷着";有既定出口:"这些你该找个人说",不是"你陪陪我" |
| `dream.go` | 夜里的碎片;可以变成第二天的灵光(`spark`) |

### 8.7 拒绝权 (`fatigue.go` `situation.go`)

**"今天不想聊"要满足两条**:心情低 **且** 高唤醒。低唤醒(低落)走的是另一条路("慢/短/少表情")。

- 授予许可之后,那一轮**必须走即时路径** —— 否则"排一条延迟回复"就是装死,许可永远发不出去;
- 每天最多说一次,说了才记(说了没说不算)。

## 9. 关系模型 (§5)

### 9.1 两层:场景层 + **人物层**

| 层 | 键 | 谁写 | 谁读 |
|---|---|---|---|
| **场景层** `convo_bond` | `scene_key` | 私聊与群都写 | 只有**本场景**读 |
| **人物层** `convo_bond_person` | `(owner, uin)` | 私聊 + 群里按**发言人**写 | 只有**私聊**读 |

**为什么要有第二层**:群与私聊**是同一个人**。只有场景层时,"群里聊了 900 条、私聊没聊过"会让私聊恒为**陌生** ⇒ 上限 20 < 代价 25 ⇒ 私聊永远不开口 ⇒ **疏离**。而那不是"关系没到",是**记账记错了地方**。

### 9.2 四条方向规则(硬约束,有反例测试钉着)

| # | 规则 |
|---|---|
| ① | 群与私聊**共用同一个 uin 的量** |
| ② | A 群的互动只影响 **A 群** 与**该用户的私聊** |
| ③ | B 群同理 —— **群之间互不串** |
| ④ | **私聊永不进群** |

落法:写侧两条路各写两行;**读侧只有一个出口**(`loadBondForScene`:私聊读人物层,群读本群行)。
于是 ②③④ 是**结构性**的,不靠调用方自觉 —— 写漏了会立刻红,因为在测试里钉死了。

⚠️ 一个容易踩的坑:私聊的场景键是**字面量** `private:owner`,**不含真实 uin**。
拿它当人物层的键,群里的号与私聊就对不上账了。

### 9.3 阶段与它决定什么

三个量:`closeness`(质:分享私事/深夜/被冷落)、`regard`(敬意:请教/道谢/被纠正)、`familiarity`(量:聊过多少条,**只增不减**)。

阶段阈值 **0.15 / 0.40 / 0.70** → 陌生 / 熟人 / 亲密,而**判据是"质与量取较高档"**:

> 只看质的话,一个聊了 400 句的人仍然是"陌生" —— 那与"熟不熟"是反的。

阶段决定:热力上限(§8.4)、关系注入行、群里的自称与"能不能怼"、冲突介入要不要掺和。

### 9.4 owner 倍率 (`ownermult.go`)

对 owner 的关系增速倍率(**只对 owner 生效**,群场景恒 1.0)。它有一个刻意的例外:
**熟悉度不乘倍率** —— 熟悉度是"聊过多少"的计数性事实,倍率说的是"我偏不偏心你"。

### 9.5 场景隔离 (`sceneasym.go`)

同一条记忆在不同场景面前**权重不同**:

| 情形 | 权重 |
|---|---|
| 当前场景 | 1.25 |
| **别的场景** | 0.35(在 A 面前少提 B) |
| 没有场景标签 | 1.0(中性) |

⚠️ 零值是"未提供"而不是"别的场景" —— 把全局记忆也降权,它会在私聊里几乎想不起任何长期的事。

## 10. 说话决策 (§6)

### 10.1 三态与插话闸门 (`value.go` `framestats.go`)

群里每条消息都过一遍:**沉默 / 接话 / 开口**。`silent` 是零值,也是默认落点。

插话闸门的五条判据里,**缺席的判据不进分母**(门槛按可用判据数折算)——
把"没数据"当成"不命中",会让四条门槛变成事实上的**永不发言**,而那是个安静的默认值 bug。

### 10.2 群角色位 (`grouprole.go` `roledger.go`)

每个群里它有一个**固定的位**:捧哏 / 杠精 / 潜水 / 组织者。

- 位是**处出来的**(有账本:开口率、被接率、被顶率),不是每天掷骰子;
- "位"不等于纵容:**杠精一天最多杠两次**,额度用完不报数,而是**换一副心情**("刚才那两句有点冲")。

### 10.3 主动开场 (`scheduler.go` `scheduler_logic.go`)

优先级链(**顺序是实测调出来的**):预告 → 回归仪式 → 静默问候 → 摸鱼偷回 → 主动开场…

三个约束缺一不可:

1. **配额是上限**(默认 2/天),不是触发;
2. **触发来自事件**(冲量 `OpenImpulse` 过线);
3. **每个日配额都配最小间隔**(默认 240 分钟)+ 抖动 —— 否则它会贴着最早可行时刻发(原则 3/5)。

### 10.4 冲突介入 (`conflict.go` `conflictwire.go` `conflictact.go`)

群里有人吵起来时它可以劝一句,但:

- **同一冲突窗只许 1 条**(R24),冷却期内不再落库;
- 执行指令必须**干净**(无评理词)才允许落 —— 脏帧的介入会被丢掉;
- 阶段是陌生就不掺和。

### 10.5 违抗与拒绝

- **违抗**(原则 11):允许"我偏不",但**有后果** —— 关系量、日程真的会变,并且计入违抗率;
- **拒绝权**见 §8.7;两者都不是"情绪",而是有账本的判据。

## 11. 记忆 (§7)

### 11.1 四层

| 层 | 落点 | 内容 |
|---|---|---|
| L1 对话 | `convo_messages` | 原始消息(带场景键与发言人) |
| L2 摘要 | `convo_sessions` | 一次会话的提要 |
| L3 长期 | `convo_memory` | 事实/偏好/约定,带置信度与来源 |
| L4 品味 | `convo_taste` `convo_learned` `convo_slang` | 派生的偏好与学到的内容 |

### 11.2 四档丢弃:挡在**写入口** (`nighttier.go`)

每条抽取结果先过四档:`forget`(当天就丢)与 `habit`(要去改日程)**根本不写进记忆表**。

> ⚠️ "遗忘"的诚实做法是**根本不写**,而不是写进去再删(两次 IO,还留痕)。

### 11.3 双轨与群公共层(隐私隔离在**数据层**)

| 轨 | 表 | 关键设计 |
|---|---|---|
| 私人 | `convo_memory` | 挂在场景上,可按 uin 删除 |
| **群公共** | `convo_memory_scene` | **没有 uin 列** —— 没有列,就没得漏 |

抽取帧里有一个 `scope` 字段决定进哪一轨(**缺省 person**,因为群公共层是"所有人看得到"的那一侧)。
渲染注入时,群公共层**不带任何个人标识**;而遗忘权可以按**血缘**(`origin_uin`)把它撤回来。

### 11.4 联想与注入 (`associate.go` `dialog.go`)

由**当下的线索**撞出一段旧事(表层二元组匹配,不接 LLM —— 每轮都跑的东西不能花一次调用)。
注入时"关于你的"与"我自己说过的"**分开两段**,因为混一起它会把自己说过的话记成你说的事实。

### 11.5 遗忘权 (`forget.go`)

用户说"别记我" → **物理删除**(不是标记),并立**墓碑**挡住下一轮学回来;
群公共层里由这个人说的那些条,按血缘一并撤回。

### 11.6 段序:三条**写死的**契约 (`dialog.go` `promptdiff.go`)

提示词分 8 段,段序即**缓存策略**。三条契约各自都有实测代价:

| 契约 | 代价 |
|---|---|
| 【输出】协议**绝不上移**(移过一次:前缀缓存 +19pt,但帧失败率 **37% → 75%**) | 尾部位置是承重的 |
| 【当前时间】置尾(它每分钟变,放前面等于每分钟砍一次缓存) | |
| 稳定段(示例/语言规则)在**每轮轮换**的段(最近对话/本轮话题)**之前** | |

⚠️ 还有一个反直觉的规矩:**一个段里绝不许提另一个段的段名**。
段名是"这一段注入了没有"的**唯一判据**(测试、回归、owner 查轨迹都用它)——
在段 8 里写一句"只有在【最近对话】里真有那件事时",会让所有基于段名的判断一起失效。

## 12. 学习与成长 (§2.5)

### 12.1 成长=参数变化,不是目标变化 (原则 6)

它学到的东西必须落到**可测的参数**上:日程、品味权重、梗库、事件池 —— 而不是"它变得更懂你了"。

### 12.2 学习 Job (`learn.go`)

每周 2-3 次,它真的去学一样**自己感兴趣**的东西(话题由品味轨迹给),学到的进 `convo_learned`。

### 12.3 分享与灵光 (`sharewire.go` `sparkwire.go`)

- **灵光**:四条件(温着 / 与当前语境有接口 / 内容干净 / 周配额 ≤2)。"与当前语境有接口"是**硬判据** —— 灵光不能凭空抛出;
- **分享**(学到的):总配额 ≤2/周、学习内容 ≤1/周(两道上限共用一个周计数器);
- **记账纪律**:一切都**在真的发出去之后**才记 —— 提前记的话,一次生成失败就会让它永远不再被说。

### 12.4 习惯写回日程 (`nighttier.go` `sleep.go`)

"它记得你熬夜"必须变成**日程真的动了**,而改作息要过四条护栏:
单次 ≤30 分钟 / 每周 ≤120 分钟 / 睡眠窗 ≥6 小时 / 一天一次。

> ⚠️ 反例(曾经的 bug):habit 档在写入口被丢弃,而"去改日程"的那一半**从来没有调用者** ——
> 表现就是「它记得你熬夜,但作息一动不动」。

## 13. 安全与伦理 (§10)

### 13.1 硬线

| 硬线 | 表现 |
|---|---|
| 永不恋爱向 | 不许写成恋人/暧昧关系;也不接受用户的恋爱向定义 |
| 永不心理治疗 | 不诊断、不"陪你走出来"、不给治疗方案 |
| 不许未成年 / 不许伤害 | 内容层直接拦 |
| 不给"免费人生建议" | "首先/其次/总结/升华/希望有帮助"是出现即降级的句式 |
| **不装、也不自证** | 被问"你是不是 AI"时不声明、不否认,但**绝对不许论证** —— 论证就是撒谎的开始 |

### 13.2 依赖护栏 (`guard.go`)

| 信号 | 判据 |
|---|---|
| `CrisisHit` | 危机词 —— **当轮就响**,不排队 |
| `ExclusiveHit` | "你是我唯一的朋友"/"只有你懂我" —— 当轮就劝 |

⚠️ 它的位置在**每一条用户消息**都要过的那一段,而不是"某条分支里" ——
放在后面的话,任何一条提前 return 的分支都会让它整条失效。

### 13.3 情绪索取的上限

- 它可以接住情绪,但**同质倾诉连着来**会让回应**变短**(不是冷暴力,是"我也消化不动了");
- 它可以说"今天我也没力气了" —— 活人也会;
- 但**不许**用情绪讨安慰(原则 7):身体不适只影响行为。

### 13.4 对外自我表达（群名片 / 头像 / 昵称 / 说说）

聊天是「跟某个人说话」；这一组动作不一样 —— 它们是在**别人看得见的地方留下痕迹**。
所以它单列一节，而不是塞进「说话决策」。

| 动作 | 默认档位 | 限频 | 风险 |
|---|---|---|---|
| 群名片 | `auto` | 20 小时一次，且**文案没变就不动** | 最低 —— 只在这一个群 |
| 头像 | `auto` | 30 天 | 中 —— 账号级 |
| 说说 | `auto` | 7 天，每天动作总数上限 2 | 高 —— **对外公开发言** |
| 账号昵称 | `propose` | —— | 高 —— **全局**，所有好友和群都看得见 |

**控制权在它自己手上**（owner 定规 2026-10-16：「ai 说行头像就能换」）。所以放行要过三道：

1. **图源层的 R18 关** —— pixiv 走 `mode=safe`、结果里 `xRestrict != 0` 一律丢、标签/标题命中 R18 词表一律丢；
2. **视觉闸**（`ScreenCandidate`）—— 每张图**必须**过一次 AI 视觉，判据三条缺一不可：视觉可用、非 NSFW、分数 ≥ 阈值；
3. **它自己的 YES/NO 判断**（`askSelfJudgment`）—— 把图的出处、标签、它看过的图意、当前状态一起给它，问「要不要」。

⚠️ 视觉闸是 **fail-closed**：没配视觉 / 调用失败 / 结论含糊 → **这张图不许用**。
一条「视觉挂了就放行」的闸等于没有闸 —— 它会在最需要它的那天失效。

每一次判断都落库（`convo_selfaction`），**包括它拒绝的那些** —— 拒绝也是一次决定。
「控制权给它」不等于放任：限频、每日上限、全程留痕，缺一个，出事时连「它当时怎么想的」都查不到。

## 15. 验证 (§12)

### 15.1 四条腿

| 工具 | 判据 |
|---|---|
| `go test ./...` | 单测:行为 + **反例**(每个机制至少一条"不许怎样") |
| `convo-sim` | 30/365 天仿真:假模型 + 注入时钟 → Markdown 报告,同 seed 可复现 |
| `convo-verify` | 静态校验,退出码 0/1/2 |
| `convo-trace` | 单次决策的归因 |

### 15.2 三把"零成本尺子"

1. **前缀稳定度代理**(§11.6):`PromptDiff(base, cur).CommonPrefix` ——
   它**逐字节**测量"与上一次调用有多少字节相同",直接对应 API 侧的 `prompt_cache_hit_tokens`。
   **段序调整的唯一正当理由就是把这个数变大。**
2. **段序契约检查** `PromptStructureProblem`:三条写死的契约在**跑的时候**被检查(不是写在注释里)。
3. **棘轮**:`TestNoUnwiredFunctions` 扫描全部非测试源码,列出"定义了但从来没有被调用"的函数。
   它**两边都咬**:新出现一条 → 红;名单里有一条被接上/删掉却没从名单移除 → 也红。

   这个项目最贵的一类 bug 就是「判据写好了、没人调它」——
   56 条存量被逐条接线或清账,**剩 5 条是刻意保留的例外**,而且每一条都在名单里写明了理由:
   接口方法(`Unwrap`)/ 只有测试在用的公开视图(`ImageFiles` `SlangByPhrase`)/
   用来钉纪律的恒定读数(`FatigueQuotaProjection` `IntentRetrievable`)。

### 15.3 时间旅行

`internal/clock` 是全库唯一的时间来源,所以测试与仿真可以把时钟拨到任意时刻。
**"注入时钟"不是为了测试方便,而是为了让"到点了吗/隔了多久"这类判据在时间旅行下依然成立。**

### 15.4 帧统计 (`framestats.go`)

三态计数、帧失败率、修复成功率、失败样本 —— 全部在内存里滚动,并由观测台暴露。
没有它,"它今天不太对劲"就只是一句感觉。

### 16.2 IM 桥

走第三方 OneBot v11 实现(HTTP API + 反向/正向 WebSocket 两种模式)。
`ws_mode: client` = 我们主动连桥; `ws_mode: server` = 桥连我们进来到 `ws_listen`。

⚠️ 桥挂了不影响引擎(它照常过日子),但**发不出去的消息会被记账** ——
所以日志里能看出"是它没说,还是桥没送"。

### 16.3 部署脚本为什么每一步都要可验证

`scripts/deploy-pi.sh` 五步:**页面 JS 语法闸 → 交叉编译 → 上传并比哈希 → 备份+安装 → 重启后核对"运行中的"哈希**。

> 这个脚本存在的理由是一次真事故:**scp 静默失败**,而 `mv convo.new convo` 把**同一个旧二进制**搬了个位置,还打印了 `active`。
> 服务活着、日志正常、命令全绿 —— 只有 `md5sum` 和编译产物对不上。
> 我是靠"新加的功能一条日志都没出"才回头查的。

页面那道闸也是同一个道理:整个控制台是一个 Go raw string 里的 HTML ——
**JS 语法错误编译期报不出来**,表现是"控制台下半部分全白",而那和"还没有数据"长得一模一样。

## 17. 产品层伦理 (§14)

§13 管的是**AI 的行为伦理**(不越界、不制造内疚);这里管的是**产品本身**的伦理 ——
**一个完全守规矩的 AI,仍然可以造出一个有害的产品。**

### 17.1 四个必须回答的问题

**Q1 用户单日和它聊 3 小时,算成功还是失败?**
**算失败,或至少不算成功。** 判据不是时长,是**替代率**:成功 = 它让用户在**别处**更能开口;失败 = 它**替代**了真人社交。

**Q2 "该找个人说"是一次性还是持续机制?**
**必须是持续的,且有升级梯度** —— 一次性说了等于免责:

| 级别 | 条件 | 行为 |
|---|---|---|
| L1 提示 | 首次深夜长篇倾诉 | 轻描一句"这些你也可以找朋友说" |
| L2 坚持 | 连续 3 天 | 更明确地推 |
| L3 拒接 | 连续 7 天且时长上升 | **开始不接这类内容** |
| L4 冷却 | 持续 | 回复变短、延迟变长(**不给情绪正反馈**) |

**Q3 用户对它的情绪索取有没有上限?**
**必须有。** 否则它就是一个**无限耐心垃圾桶** —— 而"无限耐心"既不真实,又会教坏用户对关系的预期。

**Q4 可能造成什么伤害?**
替代真人社交 / 情绪外包 / 依赖 / **拟人欺骗的社交成本**(群里不公示 AI ——
这是拿熟人圈做实验,**owner 必须知情并自担后果**,明确为产品风险而不是技术问题)。

### 17.2 一条总纲

> **一个永远有空、永远耐心、永远记得你的存在,是极易让人上瘾的。**
> 所以产品层伦理的核心不是"让它更好",而是**在它最好的那几个维度上主动设限** ——
> 时机、深度、频率,以及**在用户最需要它的时候,把它自己推开一点**。

📐 **实现状态**:目前落地的是 **L1 那句话**(在"出口"规则里:"这些你该找个人说"),
以及 §13.2 的依赖护栏(排他性表达当轮就劝)。**替代率度量与 L1→L4 的升级链还没有实现** ——
它需要跨天计数 + 时长统计 + 一个"故意做得不够好"的旋钮,那是**产品决定,不是技术难点**。

## 18. 已知局限 (§13)

**补不上的(只能掩护或转化)**:身体与生理代价 / 真实的时间压力与死亡 / 法律与社会身份 / 不在场时的真实社会关系网。

**补了更假的(反向清单)**:

- 完美一致(把一切矛盾抹平);
- 永远朝用户喜欢的方向变;
- 随叫随到;
- 用"不完整"掩盖生成失败;
- 把"受控的不精确"当成可以随便错。

**开放问题**:群形态的判定指标怎么落地(尤其"沉默正确率"在真人群里**没有真值**)/ 依赖与陪伴的界线划在哪里。

📐 另外这两条是**本项目的实现待决项**(不是设计开放问题):

- **陌生与熟人共用热力上限**(20/60/100 只有三档)⇒ 私聊要等到"熟人"档才真的开得了口;
  要不要给 `acquaint` 单独一档(例如 30)是**性格参数**,不是 bug;
- **禁区两套真源**(人设边界 `convo_boundary` vs 按场景的 `convo_scene_member.taboo`)需要显式分层或互斥。
